# 1-SEC v0.4.35

This release updates the embedded broker, Rust sidecar dependencies and the handling of mixed-trust security telemetry.

## Changes

- **Monitoring no longer borrows response authority.** Raw network syslog and unsigned Rust results can produce alerts but cannot directly authorize host actions. Auth Fortress and Network Guardian use separate histories for observations and inputs eligible for local response. Observation notifications have separate quotas and cooldowns.
- **Artifact provenance is not a checkbox.** Supply Chain Sentinel can report that a trusted CI or registry adapter rejected an artifact's provenance policy even when a signature or attestation is present. A reported pass does not suppress existing checks; 1-SEC does not verify artifacts itself or block deployments based on this signal.
- **More predictable ingestion.** Remote shared API credentials require TLS by default. Plain remote cloud endpoints are rejected. Invalid broker records stop retrying without changing the source stream's retention. An optional private checkpoint directory preserves GitHub polling progress across restarts, within a bounded lookback.
- **Dependency and release hardening.** The embedded NATS server moves to 2.14.10. The Rust sidecar updates etherparse and url and removes the unmaintained chrono dependency without changing its RFC3339 timestamp format. Artifact-producing and publishing workflows pin tools and verify signed manifests before publication.

## Before upgrading

If a reverse proxy terminates TLS off the engine host, configure TLS between the proxy and the engine before upgrading. See [transport changes and compatibility limits](2026-11-27-defense-boundaries-review.md) and [decision isolation](2026-11-27-decision-isolation.md). This does not certify every detector or policy as safe for mixed-trust enforcement. Keep dry-run enabled until the source and response settings for your deployment are reviewed. Externally managed NATS servers need their own updates.

Back up configuration and state, stop the engine, replace the matching executable(s), then restart and check health. Standalone archives include the Go engine only. Optional with-Rust archives include the matching scanner plus its configuration. The portable builds do not include native packet capture.

Verify the signed SHA-256 manifest for your download: **checksums.txt** for standalone archives, **rust-checksums.txt** for the individual scanner, or **sidecar-bundle-checksums.txt** for the optional bundles. The normal release workflow is **https://github.com/simpleending/1-sec/.github/workflows/release.yml@refs/tags/v0.4.35**, using the **https://token.actions.githubusercontent.com** OIDC issuer. See [download and verification instructions](../sidecar-bundles.md).
