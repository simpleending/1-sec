This cycle ran the local weekly report with `--days 7`, then verified its proposals against source, primary evidence, and reproducible tests. These verified source changes await a binary release. The existing v0.4.24 binaries do not contain this work.

## Collection window and evidence

The verified window is **October 16, 06:05:27 to October 23, 06:05:27 Asia/Bangkok**, exactly seven days (October 15, 23:05:27 to October 22, 23:05:27 UTC). The generator names the original local files `vuln-report-2026-10-22.*` using UTC. KEV has date-only records, so its corrected filter includes seven UTC calendar dates, October 16–22. Editorial pages are research leads rather than a date-filtered vulnerability census.

The first generation returned 196 ecosystem records and four proposals. Verification found that its NVD query rounded outward to whole days and silently stopped after 500 source records. The local script now uses exact timestamps, shares a collection endpoint, warns about capped results, queries the Go standard library, and includes locked Rust dependencies in its capability catalog. A separate verified snapshot supersedes the original collection totals. Dependency audits check the complete current graph regardless of advisory age; the October 14 Rust advisories are baseline remediation, not newly collected threats in this seven-day window. Feed records can overlap and are not a count of vulnerabilities in 1-SEC.

The corrected sample contains **8 KEV entries and 213 high/critical NVD records among the first 500 of 4,632 NVD source records**. A retry allowing full pagination timed out. The manifest records both the cap and timeout; the NVD review is incomplete and no absence-of-threat conclusion is drawn from the uncollected records.

## Implemented changes

- **Runtime certificate trust:** require Go **1.26.10** in `go.mod` and the Docker builder for GO-2026-6809 / CVE-2026-111943. Update only the Rust lock entries for **rustls 0.23.46**, **rustls-webpki 0.103.16**, and **webpki-roots 1.0.10**, resolving six dependency advisories. The 0.26.11 roots compatibility package now forwards to the patched 1.x store. No TLS verification override or new dependency exception was added.
- **External XML DTD detection:** extend the existing Go and Rust `deser_xml_entity` rule to recognize external `DOCTYPE PUBLIC` identifiers and relative `SYSTEM` references, including multiline and case variants. The report's ENTITY/internal-subset example was already covered. Plain XML and a doctype without an external identifier retain their previous behavior.
- **Go-to-Rust event compatibility:** the sidecar directly consumes Go events from NATS, but previously rejected uppercase severities, string collector sources, and `details`/`summary` instead of `data`/`description`. Compatible deserialization now accepts both formats, including omitted details and empty collector names. The existing Rust serialization format remains usable. A shared fixture is checked against actual Go serialization and then decoded, extracted, and scanned in Rust.
- **Unicode-safe match previews:** a long XML name could make the Rust matcher slice its preview inside a UTF-8 character and panic. Preview truncation now selects a character boundary while retaining the existing byte budget and ellipsis. The reproducer fails before the fix and passes afterward.
- **Local reporting maintenance:** four regression checks cover the seven-date KEV boundary, exact NVD timestamps and truncation warning, standard-library vulnerability queries, and the combined dependency catalog. Local scripts and raw reports remain ignored. Two pre-existing Rust test lint issues were corrected so Clippy can check all targets without suppressions.

## Reachability and integration limits

Go outbound HTTPS clients and configured external TLS NATS connections use certificate verification. The embedded NATS bus defaults to plaintext loopback; a static call trace through its constructor does not establish default remote exploitability. Tests issue valid certificates containing each of the eight distrusted public keys under a separate trusted test root. Go 1.26.9 accepts all eight; 1.26.10 rejects all eight, and an ordinary-key certificate succeeds. This exercises an explicit root pool, not a native OS trust-store test. The upstream Go patch also filters native Windows/macOS chains. Keep operating-system trust stores current for the rest of the deployment.

Rust's active NATS client uses native roots. The bundled roots entry also exists through the WebSocket dependency, but that client's configured connector uses its native-root configuration. The four other rustls findings require custom session logging, ECH, Brotli certificate decompression, or hybrid group prediction prerequisites that the current ring-based client does not enable. Updating their shared dependency removes the affected versions; this is not evidence of four independently exploitable product paths.

Send decoded HTTP/API payloads in `details.body` or the existing request fields through a trusted integration. The XML rule detects suspicious external declarations; it does not establish that an application resolves them, parse arbitrary binary XML, or replace safe XML parser configuration. Alerts are not inline request rejection. Enforcement depends on response integrations and mode. The shared fixture exercises the real event decoder, field extractor, and scanner without a live NATS transport or production TLS handshake. Collectors still need trustworthy metadata and protected ingestion credentials.

| Narrative goal hashes | **Rejected as specified.** A matching hash does not establish semantic authorization. Token Vault exchanges upstream tokens; it does not issue the proposed locally signed goal tokens. Existing goal/delegation/policy tests pass. An authoritative request/tool permission contract remains future work. |
| Compromised certificate trust | **Implemented at the runtime validator.** Patched Go/Rust validators, reproduced the Go failure and legitimate control, and passed the upstream Rust distrust test. | Linux descriptor polling for jail escapes | **Deferred.** The cited FreeBSD advisory was published September 29, outside this collection window, and concerns FreeBSD `FD_RESOLVE_BENEATH`. Linux inotify file events lack syscall, descriptor-transfer, and namespace provenance. Existing container-indicator tests pass; a Linux reproducer and trusted telemetry contract are required before adding this detector. |

No new dependency ignore was added.
