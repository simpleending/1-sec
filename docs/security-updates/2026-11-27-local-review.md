# November 27 defensive update (local candidate, not released)

## What changes

The supply-chain module can surface a verifier's policy rejection even when signature and provenance metadata are present. Send a normalized `build_artifact` or `artifact_deploy` event from an authenticated, trusted CI/registry adapter. The existing `artifact_name` identifies the artifact. A JSON string `"provenance_policy_result": "failed"` means the upstream verifier explicitly rejected the artifact's build identity, source revision, or release policy. This produces a high-severity `artifact_provenance_policy_failed` alert; the derived event is forced observation-only before publication and alert construction. Existing log/webhook notification policies still apply, but this verdict cannot authorize built-in host enforcement even under a custom response policy.

A reported pass is not trusted evidence that an artifact is safe. Passed, absent, unknown, unevaluated and malformed values do not create the new alert or suppress existing missing-signature/provenance checks. The engine does not verify signatures, contact registries, infer repository approvals or ship a new verifier. A compromised but policy-compliant build, an unauthenticated producer, or an unmonitored source cannot be identified using this field alone. Keep release verification and blocking at the publishing/deployment boundary. Correlate via the original event ID; emit the artifact digest in the existing hash field when available.

The embedded NATS server is updated within its 2.14 series (2.14.0 to 2.14.10) and Rust locks for etherparse (0.16.0 to 0.16.1) and url (2.5.8 to 2.5.9) are patched. The separate website candidate updates Next.js and its matching ESLint configuration from 16.4.1 to 16.4.5. A source update here does not affect an external NATS server or already-downloaded binaries.

## Why now

- [Swarm, November 17](https://www.ethswarm.org/blog/2026/bee-js-13-3-0-swarm-desktop-0-56-2-incident/) and [Databricks Threat Research, November 23](https://www.databricks.com/blog/what-5400-malicious-npm-packages-reveal-about-software-supply-chain-risk-2026) document the need to distinguish a legitimate package/publisher identity from authorized release content. Existing 1-SEC events only tested whether signature/provenance strings were present. The new contract supplies a way for an independent verifier's failure to reach the alert pipeline; it does not claim to detect these campaigns.
- [AWS threat intelligence, November 13](https://aws.amazon.com/blogs/security/amazon-threat-intelligence-observes-threat-actors-running-cybercrime-campaigns-with-artex-ai-agents/) describes abuse of compromised inference credentials. Local model-budget events do not reveal direct calls to providers. Provider-side usage and account identity telemetry are prerequisites; no claim of detection, new cloud permission, or guessed blocking rule was added.
- NATS' [leaf-node advisory](https://github.com/nats-io/nats-server/security/advisories/GHSA-p3j5-5hrq-p75h) and related MQTT advisories match the version shipped previously. Static reachability is not proof that those protocols are enabled: the default embedded broker binds to loopback with a random/configured token and does not configure MQTT, WebSocket, or leaf-node listeners.
- Rust audit confirmed [etherparse](https://rustsec.org/advisories/RUSTSEC-2026-0596.html) and [url](https://rustsec.org/advisories/RUSTSEC-2026-0592.html) lockfile matches. etherparse is used in the packet path; url is transitive, and no application-level triggering path is claimed. [chrono](https://rustsec.org/advisories/RUSTSEC-2026-0543.html) is an existing unmaintained-crate warning, not a new vulnerability; migrating its time/serde interfaces is separate work.

## Evidence and limits

Window: November 12 01:48:48 to November 27 01:48:48 UTC (15 days to cover the missed week). All expected pages returned: CISA KEV 26 additions, NVD 8,484 publications and 14,456 modifications, and GitHub 487 reviewed advisories. Counts overlap; they are not product vulnerabilities. The high-volume feed produced 1,948 prioritized candidates. Only the direct package matches, selected cases above and indicated behavior were evaluated. Other leads and inherited items remain on the ledger; this is not exhaustive coverage.

On Windows, baseline Go package and symbol scans each matched six NATS advisories; patched Go symbol scan found zero. Module checksums, Go build/vet, broker credential checks, durable-delivery restart, and synthetic provenance-event controls passed. Before the signal change both ordinary failed-verdict controls lacked an alert; the same fixtures pass after. The observation-only regression failed before hardening and passed afterwards; unrelated findings and the input event kept their eligibility. No exploit or attack replay was used. Cargo Audit found no vulnerabilities in the patched lockfile and retained the chrono warning. Portable Cargo check, formatting, URL normalization and packet-counting tests passed. The post-patch OSV lockfile check reports only the previously noted chrono maintenance warning; it did not return a clean exit. Baseline website audit reported affected Next.js (seven advisory entries); patched npm production and full audits each returned zero. Website type check, SEO and performance tests and local Next production build passed. The SEO tests require access to pinned engine git history. The local workflow's own 25 tests passed.

Not released, not deployed, not a completed broad platform matrix. Linux full-feature/native capture gates, complete race/Clippy suite and independent review remain release gates. No live systems were probed. The original operational manifest remains at its collection snapshot; do not mark the original source tree reviewed as though it contained these candidate fixes.
