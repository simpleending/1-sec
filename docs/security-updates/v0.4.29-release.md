# v0.4.29 — Safer responses and bounded detector state

Capacity warnings now stay separate from attack evidence and permit only log/webhook actions, including through approvals and action chains. Egress and compound ransomware alerts no longer authorize killing an incidental process. Ransomware victim paths remain investigative context and cannot become automatic quarantine targets; the built-in presets are updated accordingly.

Dynamic reputation, egress source/destination state, DNS query-type counters and nested scan sets are bounded. Capacity loss is reported, diagnostic counts identify lower bounds, and large positive egress byte counts cannot wrap negative before or during accounting.

Upgrade both engines to v0.4.29. Ransomware integrations should read victim paths from `affected_path`; `file_path` is no longer supplied as quarantine authority. Dynamic reputation history can expire/evict, while configured deny entries remain intact. Trusted telemetry and operator response policies remain necessary.

Regression evidence and integration limits are in [the response-safety implementation notes](2026-10-27-response-safety.md). SAML session verification and inline tool execution still require the actual service provider/runner integration; telemetry monitoring alone does not prevent either operation. This release does not claim an exhaustive audit or live attack validation.
