# v0.4.30 — sensor identity, reliable evidence and authenticated HTTP

Release date: November 5, 2026 (Asia/Bangkok).

This release packages the verified engine changes made after v0.4.29. It contains the October 30 runtime/collector fixes and November 5 enterprise-readiness, sensor-identity and authenticated-HTTP changes. Earlier implementation notes correctly described those changes as source-only at their review dates; v0.4.30 is their first packaged release.

## Included changes

- Individual ingest-only sensor credentials with explicit host/event grants, durable rotation/revocation and checks before queued containment. Enrollment and strict sensor ingestion remain opt-in. Sensor observations do not acquire operator or broker privileges.
- Runtime response uses exact local actor evidence. Victim process IDs, affected files, remote observations and unauthenticated syslog PID claims do not authorize local process/file actions. Approval decisions recheck current eligibility and expiry.
- Cold archives and sidecar delivery retain unacknowledged evidence, recognize write/close failures and avoid reporting uncertain output as durably stored. Module/sidecar lifecycle and readiness failures are surfaced.
- Credential-bearing HTTP clients reject redirects to another origin, including different ports, subdomains, HTTPS downgrades and Unicode hostname folding aliases. Legitimate same-origin redirects remain supported. Cloud delivery/ACK and archive restore require successful delivery statuses.
- Token Vault has a 15-second deadline, a 64 KiB response boundary and validation before recording token-exchange success. GitHub workflow responses and cloud command pages reject oversized or trailing JSON input.
- Environment-key loading, literal process selection, Rust matching/UTF-8 inspection, router-log handling, SSH attribution and supplied model-bundle logging-configuration inspection include the earlier source corrections and regressions.

## Downloads and verification

[Download v0.4.30](https://github.com/simpleending/1-sec/releases/tag/v0.4.30). Main Go archives and optional Rust sidecars are supplied for Linux, macOS and Windows, each in AMD64 and ARM64 variants. Go archives contain the executable, README, license, default configuration and installer. Rust files are separate sidecar executables; upgrade an installed sidecar along with the main agent.

The release contains SHA-256 manifests, Sigstore bundles and Go archive SBOMs. GitHub Actions builds and attests artifacts from the tagged commit. Publication waits for all six main archives, six SBOMs, six sidecars and four checksum/signature files. Both downloaded checksum manifests and their workflow identities are verified before publication. Native build jobs smoke-test their binary versions; downloaded Windows AMD64 binaries are also checked locally after release.

For example, with Cosign installed, verify the main checksum manifest before trusting it:

```sh
cosign verify-blob \
  --bundle checksums.txt.sigstore.json \
  --certificate-identity https://github.com/simpleending/1-sec/.github/workflows/release.yml@refs/tags/v0.4.30 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  checksums.txt
sha256sum --check checksums.txt
```

For sidecars, substitute `rust-checksums.txt` and its `.sigstore.json` bundle. Download files named by the chosen manifest into the same directory before checking it. These are workflow signatures, not Apple notarization or Windows Authenticode signatures.

## Upgrade and deployment requirements

Back up configuration, private state and current sensor revocations before replacing binaries. Stop/restart the agent and installed sidecar through the deployment's service manager; verify both reported versions afterward. Preserve the latest private sensor registry and journal. Restoring an older state backup can restore revoked credentials.

To adopt individual identities, enable `sensors.enabled`, enroll trusted producers and migrate their event submission. Set `sensors.require_sensor_ingest` only after migration to require individual credentials for HTTP events. Use HTTPS. Observation grants do not authorize local containment: local-host grants, trusted exact targets, response policy, approvals and OS permissions remain necessary. Operator and internal broker credentials remain privileged.

Configured cross-origin API redirects now fail. Point configuration at the intended canonical origin instead of relying on a redirect to transfer secrets. Large provider responses above the documented limits fail rather than partially succeeding.

Release sidecars retain the portable feature set. Packet capture requires a separate capture-enabled build, driver/library, privileges and appropriate traffic visibility. This release does not publish a new container image or Helm artifact; do not infer those deliveries from the binary tag.

## Validation and remaining limits

The packaged source has Go race/build/vet/static-analysis and package/symbol vulnerability checks, Rust format/Clippy/audit/tests, and Linux full-feature sidecar integration coverage. Release jobs add platform-native tests where available; cross-built Linux/Windows ARM64 binaries are not represented as natively executed. The release workflow verifies archives, SBOM/checksum completeness and both signature bundles before marking the release latest.

The Go/Rust and production website dependency gates are clear at the latest cycle. The conditional minimatch development-tool finding remains a documented migration constraint; no advisory ignore or forced incompatible override was introduced. Test results and complete configured feed queries do not establish exhaustive security, unlimited capacity or government certification.

Telemetry and enforcing integrations are still required. The agent does not automatically inspect every mesh client's traffic, decrypt SSH/HTTPS, enforce remote-router firewall policy, sandbox AI tools or validate exchange signing operations. Device attestation, named operator roles, durable fleet collection, replicated audit/state and measured deployment capacity remain separate work.
