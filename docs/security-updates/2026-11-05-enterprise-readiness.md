# November 5: defensive reliability and enterprise readiness

Follow-up: [individual sensor identity and credential revocation](2026-11-05-sensor-identity.md) implements the HTTP producer portion of the identity priority below. Named operator permissions and constrained broker client identities remain separate requirements. This document preserves the baseline review.

These are source changes after v0.4.29, not a new downloadable release or a certification claim. The review started at `33302ee`. The baseline fully reviewed 48 of 273 source/support paths, prioritizing ingestion, authorization, response, persistence and deployment. Architecture mapping and searches do not count as full file review. No production tenant, live attack, firewall rule or customer process was used for validation.

1SEC can provide a useful detection and response layer when connected to trustworthy telemetry. This review does not establish that it can independently protect an enterprise, government network or every application. Fleet identity, durable collection, operating capacity and audit retention remain release and deployment work.

## Seven-day intelligence cycle and second review

The local script ran with `--days 7`. Its exact interval was **October 28, 17:39:05 UTC through November 4, 17:39:05 UTC**; the local review date is November 5 in Thailand. KEV supplies dates, so its filter used the last seven inclusive UTC calendar dates. The reporting interval was not widened.

Collection found five new KEV entries and 172 high/critical records in the first 500 NVD results. NVD reported **3,074** total records: this collection is incomplete. Ten editorial pages were retrieved, but their homepage contents are not independently dated evidence that every item falls inside the window. The 177 records concern the wider ecosystem, not 177 1SEC vulnerabilities.

Every Gemini phase failed with HTTP 402 because the configured project's prepaid credits were depleted. The old script nevertheless exited zero and emitted an extraction-error object as an action item. That output is retained as incomplete, not treated as an audit. A separate primary-feed snapshot reused the exact interval, and selected CNA/vendor evidence was checked directly. The local script now preserves feed evidence, records failed/skipped model phases, stops repeated authentication/billing calls, and exits 2 for incomplete model analysis. Six local reporting tests pass. Scripts/raw reports remain ignored and are not part of the binary or its source commit.

## Operational limits and upgrade requirements

- Syslog remains unauthenticated and must have controlled network admission. The source guard prevents its local process-kill path; it does not authenticate its reported hostname, events or IP assertions. Broker credentials and write keys still identify broadly trusted producers/administrators, not individually constrained endpoint agents.
- Unknown or ambiguous SSH formats deliberately lose actionable peer attribution. General PAM/vendor formats need explicit tested adapters. The parser is not a universal authentication-log parser. Existing non-loopback relay attribution is preserved; trusted relay configuration remains deployment work.
- Archive delivery is **at least once**. ACK loss or uncertain storage outcomes can duplicate records; consumers should reconcile original event IDs. Retrying depends on retained broker data. Stream age and byte ceilings can evict evidence during prolonged outages. First-time consumers retain the prior new-messages-only behavior; existing history is not automatically replayed.
- Compression uses concatenated complete gzip members. Use restore/readers supporting standard multistream gzip. Per-record compression completion and sync cost throughput and compression efficiency; no fleet throughput claim was measured. Hardware, remote-filesystem and power-loss guarantees, directory-metadata durability, backup recovery and tamper-resistant retention are not established by these tests.
- Archive storage must be explicitly writable and persistent. Default hardened containers persist `/data/nats`, not `/data/archive`. A non-root container is not automatically a host-level process/firewall agent.
- `/health` does not yet measure consumer lag, lost collector records, detector progress or packet-capture coverage. Rust process presence does not prove successful matching/capture. Alert/approval histories are bounded RAM views, not indefinite audit retention.
- Model-configuration inspection reads only supplied text, at most 64 KiB per selected field/raw preview. It does not fetch a bundle, verify its signer, evaluate Python, inspect every auxiliary file or detect all obfuscated expressions. A trusted model gateway must supply those files before loading and enforce its own admission decision. Victim/configuration paths do not become quarantine authority.
- Runtime containment still requires trusted host/namespace evidence and OS permissions. PID reuse/start-time binding is not implemented. No real kill, quarantine, account disable or firewall operation was used to test these changes.

## Priorities before broad enterprise deployment

These are deferred engineering items with concrete acceptance requirements, not shipped features or vague prevention claims.

| Priority | Opportunity and reason it is separate work | Acceptance evidence required |
| --- | --- | --- |
| P0 | **Authenticated producer and operator identity.** Shared write/broker keys provide instance-wide trust. Per-sensor identity, host/PID-namespace authorization, credential rotation/revocation and named operator roles need a fleet identity model and backward-compatible enrollment protocol. | A producer cannot impersonate another host, publish another producer's privileged event types or approve actions; revocation and rotated credentials work without granting broad broker subjects. Tests cover HTTP, broker and relay paths. |
| P0 | **Durable collectors and detector outcomes.** File tailers lack persisted cursors/spools; broker failures can lose upstream observations. Go detector errors/panics are counted but the overall delivery is acknowledged. Blindly retrying the whole stateful fanout can duplicate counters/actions. | Bounded disk spool, explicit drop/lag counters, durable checkpoints and per-detector idempotent dispositions survive process/broker restart and full-disk tests. No acknowledged loss at the declared operating envelope; recovery cannot repeat destructive actions. |
| P0 | **Measured operating envelope and actionable telemetry health.** Unit tests do not establish enterprise capacity. Default retention is whichever byte/age limit is reached first. | Publish payload mix, sustained/burst rate, P50/P95/P99 latency, RSS/CPU/disk, queue age, drops and degraded-coverage signals during a long soak and fault injection. Set storage/retention budgets from the customer's traffic and recovery objectives. |
| P0 | **Durable, attributable audit and recovery.** Local archives and bounded histories are neither tamper-resistant nor a named-operator audit trail. | Off-host append/retention controls, decision/actor/policy/target identity, credential redaction, backup restoration and recorded action rollback/reconciliation drills. Storage and key ownership must be specified first. |
| P1 | **Identity-bound live response.** PID-only execution has a reuse window. Namespace routing and malicious-artifact quarantine require platform-specific evidence and privilege design. | Linux process identity/pidfd or equivalent start-time binding, Windows process-handle identity, namespace tests, stale-target refusal and safe actor/victim controls. Quarantine requires verified malicious artifact identity, never a path heuristic alone. |
| P1 | **Whole-model-bundle and tool-runner admission.** MONAI/Agno/Crawl4AI reinforce that weights, auxiliary config and model-selected callable names carry distinct authority. Post-event regex alerts cannot replace pre-operation authorization. | A trusted runner rejects unapproved constructors/targets and unreviewed bundle files before execution, binds approved manifests to signer/digest, and allows legitimate reviewed operations. Existing content heuristics remain secondary signals. |
| P1 | **Release/support and deployment evidence.** `SECURITY.md` advertises 1.x support while published artifacts are 0.4.x; support promises need an owner-approved policy. CI tool versions, release protections, signed offline updates and platform tests need a documented release process. | Reconciled supported versions, response commitments, reproducible signed artifacts/SBOMs, protected release identities, platform acceptance tests and staged rollout/rollback. No tag or new release was created in this cycle. |

Startups can begin with a private single-instance deployment, representative telemetry and observation/dry-run. Enterprises need the identity, audit, collection and capacity evidence above before broad live response. Government deployments additionally need their own assurance requirements and operating environment: disable external AI/cloud/reporting integrations, remove auto-enabling provider/cloud credentials, set `ONESEC_NO_UPDATE=1` where disconnected operation is required, and plan controlled offline updates. No FIPS, FedRAMP or other certification is asserted. Enabling a Go cryptographic mode alone would not validate the Rust sidecar or the overall system.

## Verification

Local validation includes the full Go race suite with the real Rust delivery integration, CLI archive compatibility, engine build/vet, package/symbol govulncheck, staticcheck, high-severity gosec, raw Go/Rust OSV, cargo audit, Rust formatting/all-feature Clippy and 207 portable Rust unit tests plus one runtime integration test. Website content/type/build checks are recorded with the blog update. Full-feature packet-capture linking still needs Linux CI: this Windows host lacks Npcap `wpcap.lib`. No live capture or production attack replay was performed.
