The warning, aggregate, victim-path and state/counter reproductions failed on the earlier implementation. Review then found that JSON float-to-int conversion could discard a large positive count before the protected counter; the actual decoded-event regression reproduced that path too. They pass with the fixes. Test executors record invocation counts without running firewall commands, killing processes or moving user files.

## Compatibility and operational limits

Dynamic reputation flags now expire or are evicted with their bounded score records. Explicit configured deny entries are preserved; cache eviction does not remove firewall rules. Capacity warnings report reduced history, not proof of a malicious source. Both reputation and egress can lose older evidence under source churn, and port-scan outer-map resets can lose prior groups. These are explicit finite-retention tradeoffs, not unlimited-load protection.

Ransomware victim paths remain available for investigation as `affected_path`. Custom integrations consuming `file_path` must use the descriptive field and must not treat victim data as a malicious executable. Built-in presets no longer move those files. Host-wide volume/compound alerts remain heuristic observations; configured IP responses and custom commands still require operator judgment. They do not acquire process ownership merely from the last packet/event.

SAML signature/replay prevention remains an integration capability, not an unpatched login admission path: this repository structurally inspects telemetry and does not create SAML-authenticated sessions. A trusted service provider must verify signing keys, issuer/audience, destination/request binding, lifetimes and atomic replay state before admitting a session. Adding a cache of unverified assertion IDs would create poisoning risks. See the [OWASP SAML guidance](https://cheatsheetseries.owasp.org/cheatsheets/SAML_Security_Cheat_Sheet.html).

Likewise, the AI module reports observed tool/delegation violations; it does not own the runner that executes a tool. Its internal comments now describe that boundary accurately. Prevention needs the actual runner to bind a decision to the invocation and fail closed before execution. No synchronous MCP/tool interception or 24-hour process-kill rule is claimed as shipped.
