# v0.4.27 — Engine boundaries and detection reliability

This release implements the verified October 19–26 weekly intelligence follow-up and addresses 13 source-audit findings. It secures the local event bus, protects monitoring credentials and raw archives, bounds hostile parser/ingestion work, unifies webhook destination checks, limits external AI data, and corrects correlation/escalation behavior.

It also restores Rust-only detection flow and source context, normalizes zero workers, repairs optional packet event routing, and corrects service-account and token-exchange monitoring. Script arrays and additional legacy pickle references receive focused detection coverage.

Upgrade both the Go tool and optional Rust sidecar. Configuration activation requires restart. CLI update checks no longer replace executable code; use the signed installer. Webhooks require public destinations. The service account must own the private data directory; existing group-writable Kubernetes volumes may require an ownership correction. Full deployment requirements, reviewed proposal dispositions, checks and remaining limits are in [the implementation notes](2026-10-26.md).

The source audit was prioritized (110/229 tracked files), not exhaustive. Five existing optional PQC dependency maintenance exceptions remain tracked. No live attack replay or packet capture was performed. Portable release sidecars do not include packet capture.
