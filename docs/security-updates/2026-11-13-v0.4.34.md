# 1-SEC v0.4.34

## More reliable event coverage

- AI Agent Containment now checks `network_connection` events for known AI service endpoints, as well as `network_request` events. Previously that declared input was skipped.
- Data Poisoning Guard now processes `inference_result` events, as well as `model_inference` and `prediction`, so low-confidence checks and drift history receive those observations.
- Module discovery now reads descriptions and event types directly from the running code's module definitions. `1sec modules info` no longer lists stale integration inputs that the modules do not handle.

The fixes have failing-before/passing-after regressions, benign controls and a real event-router test. Read the [16-module claim and test review](https://github.com/simpleending/1-sec/blob/v0.4.34/docs/security-updates/2026-11-13-module-review.md) for measured coverage and limits. No new modules or external runtime dependencies were introduced.

## Choose your download

**Recommended: `1sec-with-rust_0.4.34_<system>_<arch>`**. This archive contains the main executable, matching Rust scanner and configuration with Rust enabled. Extract it into a separate directory and run `1sec up` from there (`.\1sec.exe up` on Windows). The main engine starts and manages the scanner using the embedded broker.

**Standalone: `1sec_0.4.34_<system>_<arch>`**. One executable containing all 16 Go modules, collectors, broker, API and dashboard. No Rust process is required. The website's shell installer remains a standalone installer. Optional Gemini analysis needs provider keys and network access in either edition.

Both editions are available for Linux, macOS and Windows on AMD64 and ARM64. Rust supplements pattern scanning of connected telemetry and uses additional resources. No universal speed or detection-accuracy gain is claimed. Portable downloads exclude native packet capture; that requires a separate feature build and capture permissions.

## Verify and upgrade

Verify the appropriate signed SHA-256 manifest: `sidecar-bundle-checksums.txt` for bundles, `checksums.txt` for standalone archives, or `rust-checksums.txt` for separate scanners. The Cosign certificate identity for this release is `https://github.com/simpleending/1-sec/.github/workflows/release.yml@refs/tags/v0.4.34`, issued by `https://token.actions.githubusercontent.com`. Main archives include SBOMs. [Detailed verification instructions](https://github.com/simpleending/1-sec/blob/v0.4.34/docs/sidecar-bundles.md).

Preserve configuration and private data, stop the engine, replace the matching executable(s), then restart and check health. Existing deployments that opt into Rust must keep the scanner adjacent to the main executable and set `rust_engine.enabled: true`; do not overwrite existing policies with the example configuration.

Protection requires connected telemetry. Dry-run remains the default; enforcement requires configured policies, a supported executor/gateway and permissions. This release corrects overstated descriptions rather than claiming automatic SBOM generation, an OS tool sandbox, universal media authentication or cloud compliance certification.
