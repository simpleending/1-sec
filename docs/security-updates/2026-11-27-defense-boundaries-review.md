# Defense boundaries candidate: November 27, 2026

This is an isolated change candidate, not a shipped release.

- Plain network syslog still reaches all interested detectors. An alert can notify and be recorded, but neither a direct connection nor a loopback relay grants authority to change the host. The sidecar follows the same boundary: unsigned results remain observation-only even with older sidecar binaries. A live, signed sensor grant may still allow the previously supported named response actions.
- On non-loopback listeners, shared API credentials now require TLS or a same-host loopback proxy by default. If an existing ingress terminates TLS outside the engine host/pod, prefer TLS re-encryption to the engine. Where that is not immediately possible, `server.allow_insecure_legacy_api_keys: true` (Helm: `server.allowInsecureLegacyAPIKeys`) is a temporary compatibility option **only** if network policy/firewall excludes any client not behind that trusted proxy. Scoped sensor/operator credentials still follow their existing transport rules. Remote cloud API overrides must use HTTPS; plain HTTP is only accepted for loopback development.
- A permanently undecodable broker record stops retrying on the detector consumer and increments `messages_terminated`. The original record stays in the source stream, subject to its regular age and capacity limits. This is not an indefinite archive or deletion of audit evidence.
- GitHub polling tracks run attempts and changes in status/conclusion. It looks back at up to 60 runs per poll and reports when it cannot establish overlap at the lookback limit. Set `collectors.state_dir` to a dedicated, private persistent directory for restart checkpoints; otherwise history remains in memory. Checkpoint failures are logged and leave previous data intact. A crash before a checkpoint can yield duplicates. Runs outside the bounded window can still be missed. Ordinary file tails are unchanged and still are not durable across restart or publish failure.
- The release build and verification jobs use read-only repository permissions. The publishing job has the write/signing grants. Release tags are restricted to version-shaped tags on commits reachable from main; enforce protected tags and reviewed main in GitHub repository settings as well. This change does not resolve all remaining floating tool versions.
- Cold archive rotation is not a storage quota. Place long-lived audit archives on a separate volume monitored for available space until a retention/offload policy is implemented. Never remove preserved audit evidence to make a pressure alarm disappear.

See the separate dependency/provenance candidate note for what the verdict relies on. A reported provenance failure is investigative evidence; a reported pass does not override independent checks.

Auth and network modules still share some detector baselines across inputs. This candidate removes authority from alerts directly derived from raw syslog, not every possible indirect effect on a later alert. Keep auto-response in dry-run when combining raw syslog with enforcement-eligible feeds until state isolation is verified. Start by splitting auth failure/stuffing/spray counters, lockout lookups and successful-login resets by observation-only versus response-eligible inputs, then apply the same review to network counters.
