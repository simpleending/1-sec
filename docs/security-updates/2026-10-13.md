# October 13, 2026 security implementation

The catch-up report covers July 21–October 13. Its intelligence output was checked against the engine and converted into these code changes. Feed totals describe the wider ecosystem; they are not a count of vulnerabilities in 1-SEC.

## Release

These changes are included in [v0.4.23](https://github.com/simpleending/1-sec/releases/tag/v0.4.23). Upgrade the Go CLI and, if used, the Rust sidecar together. The release provides Linux, macOS, and Windows downloads for amd64 and arm64, checksum manifests, Sigstore bundles, and Go archive SBOMs. The prebuilt Rust sidecars use the existing portable build without optional packet capture or PQC features; those features require a source build.

## Changes

- **Auth Fortress:** `saml_response` events now detect duplicate XML IDs or attributes, misplaced or namespace-spoofed assertions, signatures referencing a different element, unsigned plaintext assertions, DTDs, and unsupported signature transforms. Input is bounded to 1 MiB of decoded XML, 64 levels, 8,192 elements, and 128 attributes per element.
- **API Fortress:** MCP provisioning uses the authenticated `user_role` supplied by a trusted collector. Decoding a bearer token's self-reported admin role no longer suppresses the unauthorized-registration alert.
- **AI Agent Containment and Token Vault:** a delegation record requires an explicit verified attestation, an identified principal, and a valid future expiry. Unverified records and records flagged for broad scopes or excessive chain depth cannot satisfy the existing sensitive-action check or authorize a connected account through Containment. Token Vault authorizations expire, renewal replaces the previous grant, and tool-use monitoring requires both user and agent identities.
- **LLM Firewall:** sensitive-file reads followed by encoding and an HTTP request are correlated within a rolling 60-second window. Stale steps expire. Markdown destination checks parse the actual hostname, so `localhost.attacker.example` or `localhost@attacker.example` cannot impersonate a local destination. Concurrent web-taint/output processing reads taint state under the existing lock.
- **Dependencies:** the earlier implementation commit `abdf49f` requires Go 1.26.9, `github.com/klauspost/compress` v1.18.7, `golang.org/x/crypto` v0.56.0, and `golang.org/x/sys` v0.47.0.
- **Rust dependency maintenance:** the YAML parser now uses the YAML organization's maintained `yaml_serde` v0.10.7 fork. This removes `unsafe-libyaml` and resolves RUSTSEC-2024-0449, an unmaintained-package advisory issued October 12, 2026. The yanked transitive `chacha20` v0.10.0 lock entry is updated to v0.10.2. YAML alias/capture-settings compatibility and malformed-input error handling have regression coverage.

## Integration contract

Send SAML events through the normal event ingestion path:

```json
{
  "type": "saml_response",
  "source_ip": "192.0.2.10",
  "details": {
    "saml_response": "<samlp:Response ...>...</samlp:Response>"
  }
}
```

`details.saml_response` accepts UTF-8 XML or standard base64. `details.body` is the fallback and also accepts an HTTP form containing exactly one `SAMLResponse` field. The detector emits a high-severity `saml_structure_violation` alert through the existing event bus and response pipeline. It does not verify signature values, IdP keys, issuer/audience, expiry, or replay. Encrypted assertion contents remain opaque. The service provider must perform those authentication checks.

For MCP provisioning, a trusted authentication integration must populate `details.user_role` after verifying the token and its intended resource. Raw request claims are not authenticated context.

For `agent_identity_delegation`, the trusted identity integration must verify the attestation and its binding to the exact `agent_id`, `delegated_by`, `scopes`, and `expires_at`, then set **boolean** `details.attestation_verified: true`. An arbitrary string or an agent's assertion is insufficient. Existing integrations that do not supply verification will receive delegation alerts for sensitive operations. Protect the ingestion credentials and do not let an agent declare its own trusted verification metadata. This is a telemetry-based detector, not a cryptographic identity service or a complete per-action authorization policy.

Local/private IP treatment in markdown output follows the existing policy; hostname parsing does not resolve DNS or authorize a destination.

## Verification

Regression cases cover unsigned SAML, duplicate IDs/attributes, moved assertions, incorrect signature references, DTDs, hostile transforms, XML resource limits, forged MCP admin claims, forged/expired delegation, connected-account authorization, sensitive-read exfiltration chains, stale tool steps, and deceptive markdown hosts. The engine package tests with race detection, Windows binary build, vet, staticcheck, and gosec pass. Govulncheck reports zero reachable findings; the unused deprecated OpenPGP package advisory remains in the required `x/crypto` module. The blog repository's TypeScript check also passes.

Rust has 194 passing tests with PQC enabled and packet capture disabled locally. All-feature Clippy and formatting checks pass. Windows full-feature test linking requires the unavailable `wpcap.lib`; CI runs that configuration on Linux with libpcap. Cargo audit passes with five existing optional PQC/paste maintenance warnings. The repository OSV scan passes using the existing, unchanged exceptions for those warnings. No YAML or yanked-package exception was added.

## Report dispositions

Five current items are implemented: Go dependency/toolchain updates, SAML structural detection, verified agent identity, exfiltration correlation, and Rust dependency maintenance. The SAML research lead now has primary evidence and reproducible tests. The external-agent identity lead produced the concrete MCP, delegation, and Token Vault fixes above.

SafeTensors structure checks, Linux inotify monitoring, WebSocket framing, and overlapping event scans were already present. They are not new features in this cycle. Full binary deserialization parsers, enterprise-specific RBAC schemas, cloud-CLI traffic baselines, and dynamic external driver feeds remain deferred: those proposals need validated protocol fixtures, customer policy inputs, or a trusted feed contract. The optional PQC provider/paste maintenance warnings also remain deferred pending a maintained provider migration with interoperability coverage. All five deferred items are recorded for the next cycle.
