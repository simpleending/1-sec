# v0.4.26 — Local dashboard and secure cloud operations

This update adds an optional local web dashboard and coordinates the engine with the website's account, enrollment and remote-command fixes. Local CLI detection and response remain independent of cloud services.

## Changes

- Run `1sec dashboard --web` to print the local GUI URL. The GUI uses the engine's existing API authentication and read/write scopes. Credentials stay in page memory; static assets contain no operational data.
- Inspect engine status, alerts, modules, enforcement, approvals, correlations and supported operational snapshots locally. Write keys can use existing policy, approval and configuration-reload operations. Runtime edits do not automatically persist to the configuration file.
- Cloud reporting and remote commands are separate opt-ins. Remote commands require an enrolled machine credential, a unique `instance_id`, and explicit `remote_commands_enabled: true`.
- Commands bind to the selected instance and require a successful exclusive claim before execution. Wrong-instance, unscoped, expired and unsuccessfully claimed commands do not execute. Pending command pagination no longer silently skips later pages.
- Approval setting changes validate the entire patch before updating both the displayed configuration and live gate. Heartbeats distinguish enforcement policy state from detection-module state.
- The optional Rust sidecar uses the security-patched Tokio 1.51.6 LTS line. No enabled AsyncFd call path was found; the update removes the affected dependency version.

## Coordinated website update

The web deployment authenticates billing access, protects the initial checkout key with an HttpOnly browser claim, preserves account identity and roles across rotation, enforces shared subscription entitlements and quotas, hides sibling credentials, and enrolls separately revocable machines. Retained cloud records have bounded cursor pages and owner-configurable retention rather than silent fixed history caps.

Install v0.4.26 before using the website's new generated cloud configuration. Existing owner keys can report telemetry but cannot use the new device-only command claim protocol. Generate a machine credential for each instance. Retention is enforced lazily during reads, not by a scheduled storage-erasure job. A claimed command with no terminal result has an uncertain outcome and is not automatically retried.

## Verification and limits

The Go race suite, engine build, vet and vulnerability reachability checks pass locally. Rust formatting, all-feature/all-target Clippy, portable build, 197 PQC-enabled unit tests and the new runtime integration test pass. The local Windows host lacks the packet-capture linker library; Linux CI provides the full-feature build and test gate. Dependency scans retain the existing five optional PQC/paste maintenance exceptions.

See [the implementation and verification notes](https://github.com/simpleending/1-sec/blob/v0.4.26/docs/security-updates/2026-10-25-dashboard.md) for individual audit dispositions, upgrade details and remaining limits. Portable release sidecars omit optional packet capture and PQC; source builds can enable those features.
