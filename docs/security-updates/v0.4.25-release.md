# v0.4.25 — TLS trust, event compatibility, and detection reliability

This release includes the verified October 23 engine changes previously available only in source. Upgrade both the Go CLI and the optional Rust sidecar.

## Changes

- Patched TLS trust handling: Go 1.26.10 and the updated locked Rust TLS dependencies reject the compromised certificate keys covered by the upstream fixes.
- Go-to-Rust event compatibility: the sidecar accepts the Go engine's severities, collector sources, `details`, and `summary` fields. A shared serialization fixture verifies payload extraction and scanning.
- External XML DTD detection now includes PUBLIC identifiers and relative SYSTEM references. Rust match previews truncate at UTF-8 boundaries instead of panicking on long Unicode input.
- Media screening validates PCM audio and decodes bounded JPEG/PNG frames before analysis. Silence, static scenes, and unsupported container bytes no longer become synthetic-media evidence. Unsupported media produces an informational unavailable status.
- Ransomware activity is scoped to reporting hosts and processes, counts distinct files, expires continuous activity, and preserves response targets. Critical entropy-based batch detection requires reported before/after entropy increases. Missing disk offsets and writes to ordinary files or non-disk devices no longer assert MBR destruction.
- Local process termination and quarantine reject explicitly remote reporting hosts; configured response policies, approvals, and dry-run behavior continue to control actions.
- Post-quantum assessment requires matching passive-capture and classical key-establishment evidence. Offered groups and TLS 1.3 cipher suites do not prove the negotiated exchange. Unknown algorithms remain unassessed; AES-128 is not labeled broken solely by a theoretical Grover speedup.

## Downloads and verification

Go CLI archives and portable Rust sidecars are built for Linux, macOS, and Windows on amd64 and arm64. The release includes SHA-256 manifests, Sigstore bundles, Go archive SBOMs, and GitHub artifact attestations. Portable Rust sidecars omit optional packet-capture and PQC features; those require a source build.

The Go race suite, engine build, vet, staticcheck, and vulnerability reachability checks pass for the implementation. The WAVE parser fuzz run completed 166,297 executions. The Rust suite has 197 passing tests with optional PQC enabled and packet capture disabled, with formatting and all-feature/all-target Clippy checked. The repository-wide dependency gate retains the existing five optional PQC/paste maintenance exceptions; no exceptions were added.

## Integration requirements and remaining limits

Send decoded request content and trustworthy process/host attribution through protected ingestion. Ransomware entropy-transition escalation needs accurate `entropy_before` and `entropy` observations; ordinary file notifications do not universally supply these. Remote PIDs must be handled by an executor on the reporting host. Regression tests exercise detection-to-policy in dry-run mode, not live malware or guaranteed prevention before data damage.

Audio screening accepts mono PCM16LE at 16 kHz and examines at most the first second. Video screening accepts up to eight bounded JPEG/PNG frames; encoded media needs upstream decoding. Statistical media scores remain uncalibrated heuristics, not validated deepfake authenticity verdicts.

The crypto module assesses inventory and capture risk; it does not retrofit post-quantum encryption into other applications or establish an interceptor's intent. XML detections are alerts, not safe parser configuration or automatic inline request rejection. Keep operating-system trust stores current.
