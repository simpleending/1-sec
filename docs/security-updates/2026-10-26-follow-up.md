# October 26 follow-up: observation identity and bounded inspection

Target release: v0.4.28. This implements four follow-ups from the October 19–26 intelligence and source-audit cycle. It does not collect another reporting window or increase the prior audit's 110/229-file coverage claim. The [original weekly decisions](2026-10-26.md) remain historical records.

## Implemented changes

| Item | Change | Regression evidence |
| --- | --- | --- |
| Event deduplication | Fingerprints retain the complete serialized event, including nested details, full summary/raw bytes, routing/attribution, ID and timestamp. Canonical JSON map ordering makes an unchanged delivery replay stable. Events without both ID and timestamp, or with unserializable details, bypass deduplication rather than risking suppression. | `TestDedupPreservesChangedDetectionInput`, `TestDedupStableMapOrderAndUnhashableInput`, `TestDedupPreservesIndependentObservations`; real engine/bus/module tests `TestChangedBodyReachesDetectionThroughEngineDedup` and `TestIndependentMFAAttemptsReachRateDetection`. |
| Input normalization | Go and Rust numeric-entity searches inspect only the already accepted ten-byte window. Unterminated inline comments copy the remaining tail once instead of repeatedly searching it. Accepted decoding, malformed output and UTF-8 boundaries are preserved. | Go `TestBoundedNormalizationPreservesEntityAndCommentSemantics`; equivalent Rust normalizer tests, including 64 KiB malformed inputs. |
| Packet state | Source and SSH tracking are capped at 4,096 identities each; per-source port sets stop growing at the existing 20-port threshold. WebSocket state retains its 4,096-flow cap. FIFO admission replaces the oldest history without a full eviction search for every new identity. Each capacity eviction emits a `tracking_capacity` packet anomaly, which the existing Network Guardian packet-anomaly path exposes. New WebSocket flows remain inspectable after saturation. Reset/expiry also clears the associated admission queues. | Source, SSH and WebSocket saturation/expiry regressions verify bounded maps, continued admission, capacity warnings and detection on admitted flows. Stateless oversized SSH detection remains independent of admission. |
| Unused dependency chain | Removed optional `pqcrypto-mlkem`, `pqcrypto-mldsa` and `pqcrypto-traits`, plus their now-unused transitive packages. The lockfile drops from 265 to 256 packages without upgrading retained dependencies. Removed all five OSV advisory exceptions. | Source/call-site search finds no consumers of the removed APIs; locked compatibility-feature tests and all-feature Clippy pass. Cargo audit and OSV report no Rust findings or exceptions. |

The prior dedup implementation suppressed changed-body detection inputs. Review also reproduced six independent failed MFA attempts collapsing into one event before Auth Fortress could count them. The final regressions fail before the relevant fix and pass afterward. Delivery replay suppression remains tested. Collectors must reuse the observation's identity for a replay; independently generated observations are deliberately retained, even when their content is equal. Cross-collector content similarity alone no longer establishes a duplicate.

The first packet-capacity candidate silently refused new identities. Saturation tests reproduced the coverage gap; the shipped implementation instead admits the new identity and reports evicted coverage. FIFO eviction can still remove useful older evidence, so sustained identity churn can reduce stateful detection. A capacity warning is a reason to investigate load and capture placement, not proof that all traffic remains covered.

## Normalization measurement

Same-host Go microbenchmarks (`BenchmarkUnterminatedNormalization`, 100 ms per case) measured repeated malformed openers. Approximate 64 KiB entity normalization changed from 22.44 ms to 0.77 ms; unterminated comments changed from 115.27 ms to 0.035 ms. The 1 KiB and 16 KiB cases also ran. These synthetic function measurements demonstrate removal of repeated suffix searches; they are not production throughput or whole-engine latency claims.

## Crypto scope

This removes unused build dependencies, not an active encryption provider. No sidecar source used their functions or the `pqc` feature. An empty `pqc` compatibility feature remains so existing build commands continue to work. No keys, ciphertext, wire protocols or deployed cryptographic operations are migrated. The Go Quantum Crypto module's inventory, TLS and risk-monitoring behavior is unchanged; it does not gain encryption or migration capability.

The removed exceptions were RUSTSEC-2024-0436 and RUSTSEC-2026-0161, 0162, 0163 and 0166. Their disappearance follows removal of the affected packages, not a claim that their upstream advisories were fixed.

## Verification and limits

Local checks pass:

- `go test -race -timeout 120s ./cmd/... ./internal/...` including the real-engine MFA and changed-body regressions.
- Engine build, vet, repository-configured staticcheck and high-severity gosec.
- `govulncheck ./cmd/... ./internal/...`: zero reachable vulnerabilities. GO-2026-5932 remains required-only, in an unimported deprecated OpenPGP package with no fixed release.
- OSV over Go and Rust lockfiles: zero actionable findings, with no Rust advisory exceptions.
- Rust formatting, `cargo clippy --locked --all-features --tests -- -D warnings`, and `cargo audit`.
- `cargo test --locked --no-default-features --features pqc`: 204 unit tests and one runtime integration test. The empty compatibility feature does not imply PQC algorithm tests.

Hosted Linux CI must additionally pass full-feature libpcap builds/tests before release verification. Local Windows lacks Npcap's `wpcap.lib`; no live packet capture or production attack replay was performed. Portable release sidecars do not include capture. Packet inspection remains a heuristic over observed plaintext packets, without complete TCP reassembly, encrypted SSH inspection or a verified WebSocket handshake.

Upgrade both engines to v0.4.28. Existing v0.4.27 ownership, authenticated bus, public webhook destination and restart prerequisites still apply. Detection requires trustworthy relevant telemetry. Automated actions depend on configured policies, approval/dry-run settings and operating-system privileges. Remaining priorities include unreviewed source, broader detector-state load measurements, trusted SAML/session verification and inline tool-runner admission.
