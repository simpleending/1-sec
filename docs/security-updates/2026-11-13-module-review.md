# Module claims and verification — November 13, 2026

## Scope and result

Reviewed the 16 built-in module descriptions, declared event subscriptions and dispatch paths against their implementation and existing regression suites. Reconciled the current README, CLI catalog, website module summaries and setup documentation. This is a feature-contract review, not a new weekly CVE collection or a certification that every attack or branch is tested. The November 12 vulnerability cycle remains the latest completed intelligence cycle.

Two detection paths were actually broken: AI Agent Containment subscribed to `network_connection` but did not dispatch it, and Data Poisoning Guard subscribed to `inference_result` but did not dispatch it. Both now reach their existing detectors. Regressions failed against the previous code and pass after the fixes, including benign controls and a real registry-dispatch check. No module, runtime service or dependency was added.

`1sec modules` and `1sec modules info` previously maintained separate, stale lists containing unsupported inputs such as `query_exec`, `identity_create` and `llm_prompt`. They now derive descriptions and event subscriptions from the same module constructors used at startup. Catch-all modules report `*`. Existing canonical inputs are unchanged; this does not introduce aliases for previously advertised nonexistent inputs.

## Dispositions and remaining work

- **Implemented:** the two event alias fixes, regression tests through handlers and registry, and runtime-derived CLI discovery.
- **Corrected claims:** automatic SBOM generation/feed lookup, OpenAPI parsing, cryptographic artifact verification, OS agent sandboxing, full disposable-domain coverage, automatic canary deployment, universal media authentication, whole-estate crypto inventory, cloud compliance certification and unmeasured Rust speedups. These features are not shipped merely because older text described them. Current summaries now state the implemented checks and prerequisites. Landing and setup docs share the same module descriptions, including the optional sixteenth AI module.
- **Already covered:** existing source tests exercise the detection families listed above, including malformed inputs, selected evasions, benign controls and attribution boundaries. A dispatch/subscription comparison found no other omitted event aliases in the 16 module handlers; Token Vault delegation and the two catch-all modules were reviewed separately.
- **Deferred with concrete limits:** an independently labelled attack/benign corpus, detector precision/recall calibration, all-platform hardware execution, representative sustained-load measurements and a complete historical-article review are separate validation projects. Local statement coverage is 68.7–95.1%, so an assertion that every feature and branch is thoroughly tested would be false. Historical research articles are not a substitute for the current module contract.

## Verification

Local verification passed: full `go test -race -timeout 180s ./...`, all module suites with coverage, engine build, `go vet ./...`, and `govulncheck ./...` (no vulnerabilities found). The 16 packages contain 982 top-level Go tests, plus 14 in the optional Token Vault package; subtests add individual cases. New tests are `TestShadowAINetworkEventAliases`, `TestInferenceEventAliases`, `TestModuleCatalogMatchesRuntime` and `TestRuntimeRoutesDocumentedDetectionAliases`.

Rust portable tests passed: 207 unit tests plus one runtime-compatibility integration test. `cargo audit` reported no findings. Native packet capture is excluded from portable release builds; Linux CI covers the all-feature build/test and dependency gate. No Rust detection algorithm or dependencies changed in this review.

Rust formatting passed. On Windows the strict portable Clippy run reported seven pre-existing dead-code diagnostics for packet-capture configuration/publisher types excluded by `--no-default-features`. The portable check passed with `-D warnings -A dead_code`; the exception is limited to that existing feature-gated code. The Linux all-feature CI check retains `-D warnings` without that exception. The Rust package version was aligned with the release; an unsupported source-comment speedup claim was removed.

## Recommended download

The website recommends the one-archive Rust bundle and retains standalone links for every platform. Rust supplies another pattern set and normalization/matching path over connected telemetry; it adds CPU/memory/broker work and does not replace Go detector work. No end-to-end speed or accuracy improvement was measured. See [setup, verification and tradeoffs](../sidecar-bundles.md).

References for the implementation/test approach: [Go testing](https://go.dev/doc/tutorial/add-a-test) and the installed [regex 1.12.3 RegexSet API](https://docs.rs/regex/1.12.3/regex/struct.RegexSet.html). Test coverage is evidence about executed code, not a security guarantee.
